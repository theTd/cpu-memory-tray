# CPU / 内存托盘监控

适用于 Windows 10/11 x64 的小型 Rust 应用。双击 `cpu-memory-tray.exe`，只显示一个托盘图标，没有主窗口和控制台。图标可能收在托盘的隐藏图标区域中，可手动拖到常显区域。

## 使用

- 图标上半部：CPU 总占用率；下半部：物理内存占用率，纵轴均为 0–100%。
- 每根历史柱按当时的占用率分级：**绿色 <50%，黄色 50%–<80%，红色 ≥80%**。
- 从左到右表示从过去到现在；一列有多个采样时保留峰值。
- 悬停显示当前 CPU、内存百分比，以及已用 / 总物理内存 GiB。
- 右键 → 时间窗口：10 秒、30 秒、1 分钟、5 分钟、15 分钟、60 分钟。
- 右键 → 采样间隔：0.5、1、2、5、10 秒。
- 右键 → 开机自启：勾选后，在当前用户登录 Windows 时自动启动；再次点击取消。
- 默认窗口 60 秒、间隔 1 秒；右键 → 退出。

时间窗口与采样间隔只对本次运行有效。开机自启默认关闭，勾选后保存在当前用户的 Run 注册表项中，无需管理员权限；菜单重新启动时读取该状态。勾选表示已注册自启，Windows 的启动应用设置仍可另行禁用。开启前请先把 EXE 放到固定位置，移动或删除 EXE 后原路径不会自动更新。重复启动会直接退出第二个实例。

## 资源与行为

应用代码只有一个 UI / 采样线程，以 Windows 消息循环阻塞等待，没有忙轮询和自建后台线程。Windows Shell / COM 自身可能建立系统内部线程或缓存。

历史按实际时间记录，切换采样间隔不会拉伸已有数据。保留最近 1 小时，最多 7201 个样本，预分配固定容量。没有采到的数据保持空白，不伪造历史；启动后需等待一个采样周期才出现第一根柱。打开原生右键菜单时采样可能暂停，关闭后恢复。

托盘和菜单由 `tray-icon` / `muda` 的所有权封装管理；每次刷新替换并释放旧图标。定时器、单实例互斥体和 COM 初始化由 RAII 配对释放，正常退出时移除托盘并释放窗口、图标和菜单。临时采样 / Shell 刷新错误会在下个采样周期重试。

运行时不联网，不采集进程列表，不保存监控历史或采样配置。只有点击开机自启菜单时，才写入或删除本应用的 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\CpuMemoryTray` 值；不更改其他启动项。仅显式运行资源测试时，会在 EXE 同目录写测试报告。

CPU 使用 `GetSystemTimes` 的相邻采样差分；内存使用 `GlobalMemoryStatusEx` 的总物理内存减可用物理内存。超过 64 个逻辑处理器的系统存在 Windows 处理器组统计范围限制，本版本不做处理器组聚合。

## 构建

需要 Rust 1.90+、Windows MSVC 工具链与 Windows SDK。普通联网环境：

```text
cargo build --release --locked -j 2
cargo test --locked -j 2
cargo clippy --locked --all-targets -j 2 -- -D warnings
```

输出在 `target/release/cpu-memory-tray.exe`。不需要安装额外运行服务或 WebView。

## 资源回归检查

关闭已有实例后，在真实 Windows 桌面中运行：

```text
cpu-memory-tray.exe --smoke-test
```

测试先预热 Shell 的进程级缓存，再连续 500 轮切换时间窗口、切换并替换定时器、刷新采样与图标，比较本进程句柄、GDI/USER 对象与私有提交内存，并在释放应用对象后检查计数。报告为同目录的 `cpu-memory-tray.smoke-test.txt`。测试失败返回退出码 1。沙箱或无法访问通知区域的会话不能完成这项测试。

7 项测试覆盖历史容量与过期清理、真实时间定位、间隔变化、峰值保留、窗口边界、颜色分级、CPU 差分、中文/空格路径的引号处理及注册表启用/取消。注册表测试只在独立临时测试键中运行并自动清理，不修改真实启动项；限制注册表写入的沙箱无法执行该项测试。有限回归测试不能证明所有系统和无限运行时间下绝无泄漏。

## 源码

- `src/main.rs`：入口与错误处理。
- `src/graph.rs`：有界历史、按时间压缩、分级颜色与图标绘制。
- `src/windows_app.rs`：系统采样、托盘菜单、消息循环和资源生命周期。
- `src/startup.rs`：当前用户的开机自启状态与注册表句柄管理。
- `Cargo.lock`：固定依赖版本，便于复现。

直接依赖只有 `tray-icon` 与 `windows-sys`。
